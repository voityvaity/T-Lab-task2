# T-Lab 2026 · Задание №2

## RL для последовательных рекомендаций: выигрыш в прогнозируемой награде и потеря релевантности

**Статус:** самостоятельное экспериментальное исследование на Yambda-50M. Представленные ниже ЧИСЛЕННЫЕ результаты подтверждены [успешным GitHub Actions run №40228502903](https://github.com/voityvaity/T-Lab-task2/actions/runs/40228502903) на коммите `f388152870156bab1962b2cba1ab015819a7719c`. После запуска были обнаружены методологические ограничения и внесены исправления **в новую версию кода**, которая ещё требует собственного smoke и сопоставимого реального запуска. Исправления НЕ подменяют численные результаты исходного прогона.

**Главный результат:** RL повысил *оценку* дослушивания независимой reward-head, но пятишаговая RL-политика снизила test NDCG@10 примерно на **7,6%** по сравнению с supervised GPT-2. В ходе свободной пятишаговой генерации модель почти всегда возвращалась к объектам из истории. Это содержательный **отрицательный результат**, а не доказательство улучшения удовлетворённости пользователей.

## 1. Задача и гипотеза

Дано прошлое пользователя `[item_1, item_2, …, item_t]`. Нужно обучить GPT-2 предсказывать следующий прослушанный трек, затем по наблюдавшейся доле дослушивания обучить reward model и дообучить GPT-2 с RL. Проверяются релевантность, краткосрочная прогнозируемая награда, повторение рекомендаций, сдвиг пятишаговых траекторий и ограничения перехода к долгосрочным целям.

**Нулевая гипотеза:** увеличение модельной награды может сопровождаться ухудшением фактической offline релевантности и/или эксплуатации ошибок reward model. Для ответа **не требуется**, чтобы RL победил.

Методологические ориентиры: [GPTRec-RL (Petrov & Macdonald, 2024)](https://arxiv.org/abs/2403.04875), [Session-Level RL (2026)](https://arxiv.org/abs/2607.02818), [ROLeR](https://github.com/ArronDZhang/ROLeR). Реализация своя: использует **не** точный GPTRec teacher–student, PPO или оригинальный ROLeR.

## 2. Данные и протокол

Источник: [Yandex Yambda](https://huggingface.co/datasets/yandex/yambda), версия `flat/50m/listens.parquet`, зафиксированная ревизия `e8b04458db77e2fb30a24e65f78923fa48b7d297`.

- **256 пользователей**, случайно выбранных **по TRAIN-периоду**, а не по будущей активности.
- Словарь: 4094 самых частых TRAIN-трека + специальные PAD и OOV (итого 4096 токенов).
- Временные границы: TRAIN до 18 200 000; validation 18 200 000–22 100 000; test после 22 100 000. Время — секунды, дискретизированные с шагом 5 секунд; числа не обозначают Unix-время.
- Использовано **100 000** обучающих next-item примеров, **5 293** validation запросов и **5 775** test запросов.
- Левое дополнение контекста PAD, OOV для неизвестных объектов. **Основные Recall и NDCG включают OOV-цели как нулевые попадания**, а не выкидывают их.
- Покрытие оцениваемых test-целей словарём обучения: **27,76%**. Это ограничивает максимальное достижимое качество.

При формировании основных train/validation/test примеров события с одинаковой временной меткой не подмешиваются друг другу в историю. **Уточнение после эксперимента:** dense causal CE на коммите исходного прогона ещё могла содержать переходы между треками с одинаковым временем *внутри уже накопленной истории*. В дальнейшем исправлено сохранение времен каждого токена и исключение неупорядоченных переходов. Измеренные ниже значения относятся к старому, явно указанному SHA и **не считаются измеренными на исправленном обучении**.

## 3. Модели и обучение

**Supervised:** GPT-2 с двумя transformer слоями, ширина 96, четыре attention heads, 48 треков контекста. Обучение по смешанной причинной cross-entropy (один следующий трек + переходы в контексте), до 1500 шагов; checkpoint по validation CE.

**Reward model:** `r = clip(played_ratio_pct / 100, 0, 1)`. Прогноз на наблюдавшихся прослушиваниях строится через TRAIN-only сглаженный средний процент дослушивания каждого трека и обучаемую поправку на контекст. Применяется MSE; checkpoint выбирается по валидации. Optimized и uncertainty heads используют одних TRAIN-пользователей, auditor — отдельную TRAIN-подвыборку; замороженный энкодер GPT-2 общий, поэтому auditor не полностью независим.

**RL:** REINFORCE с leave-one-out baseline и KL относительно замороженной GPT-2; в этом run `β=0.1`, 120 шагов RL на конфигурацию. Сравнены `completion` и `conservative` (штраф за разногласие двух heads), а также горизонты **1** и **5**. Дополнительно базовые Popularity, Sequential Rules, Smoothed Transition, GPT-2 с постранжированием (α=0,1,3). Для всех методов одинаковый train-only каталог и отложенный test.

**Выбор по validation:** положительное улучшение auditor-predicted completion при ограничениях на относительную и абсолютную потерю validation NDCG и проверке качества reward-head против константы. Test не используется при выборе конфигурации. Критерий по predicted reward *не является* доверительной causal оценкой реального поведения.

## 4. Реальные результаты на test

| Вариант | Recall@10 | NDCG@10 | Auditor predicted completion@10 |
|---|---:|---:|---:|
| GPT-2 без RL | 0.040346 | **0.021921** | 0.587651 |
| GPT-2 + rerank α=1 | 0.039654 | 0.021594 | 0.587954 |
| GPT-2 + rerank α=3 | 0.038095 | 0.020646 | 0.588303 |
| RL completion, 1 шаг | 0.041039 | 0.021881 | 0.588315 |
| RL completion, 5 шагов | 0.038268 | **0.020249** | **0.590192** |
| RL conservative, 1 шаг | 0.041558 | 0.021839 | 0.588210 |
| RL conservative, 5 шагов | 0.038268 | 0.020006 | 0.589773 |
| Popularity | 0.009870 | 0.004868 | 0.565231 |
| Sequential Rules | 0.028745 | 0.018070 | 0.571620 |
| Smoothed Transition | 0.038615 | **0.024026** | 0.577338 |

Наблюдения:

1. По validation выбран `rl_completion_h5_kl_0.1`. На test NDCG снизился с 0.021921 до 0.020249, то есть примерно **−7,6%** относительно GPT-2.
2. Auditor score увеличился с 0.587651 до 0.590192, но это **только прогноз**, а не наблюдаемое удовлетворение. Это именно конфликт между двумя целями, который требовалось изучить.
3. Парный bootstrap по пользователям для разницы test NDCG выбранного RL против GPT-2: **95% CI [−0.003125; −0.000312]**. В пределах данной когорты интервал исключает ноль; выводы нельзя распространять на весь сервис.
4. На этом test простой Smoothed Transition оказался лучше GPT-2 по NDCG (0.024026 против 0.021921); нельзя называть наш supervised baseline безусловно сильным.
5. Невозможно приписать отличие этого run от малого pilot одному улучшению: одновременно поменялись объём данных, размер словаря, количество пользователей и обучение.

## 5. Проверка reward model

| Reward head | Validation RMSE | Константа TRAIN-среднее | Test RMSE | Константа TRAIN-среднее |
|---|---:|---:|---:|---:|
| Optimized | **0.42865** | 0.43949 | **0.45164** | 0.45922 |
| Auditor | **0.44080** | 0.44199 | **0.45426** | 0.45554 |
| Uncertainty | **0.42796** | 0.43949 | **0.45793** | 0.45922 |

Optimized действительно лучше константы по RMSE, но auditor — лишь **с небольшим отрывом**. Обе оценены только на наблюдавшихся взаимодействиях; на *вымышленных* пользователем ещё не прослушанных рекомендациях качество прогнозирования неизвестно. Две согласные модели с одним энкодером не создают калиброванной нижней границы награды.

## 6. Многошаговая генерация и объяснение отрицательного результата

В «свободном» пятишаговом режиме каждый предсказанный item добавлялся в историю, **как будто пользователь его прослушал**. Это полезный стресс-тест из условия, но не симулятор реальных откликов. Со второго шага доля рекомендаций, уже встречавшихся в текущей истории, составляла приблизительно **98–100%**. При этом модельная награда росла: для выбранной RL-политики примерно **0.6397 → 0.6656** с шага 1 до шага 5.

По **219** реальным строго последовательным пятишаговым окнам JS-divergence между предсказаниями на реальном и сгенерированном контексте возрастала к пятому шагу (GPT-2 ≈0→0.152; RL ≈0→0.159). Это согласуется с распределительным сдвигом и накоплением ошибок. Достоверного эффекта на реальных будущих рекомендациях эти диагностические величины не идентифицируют.

## 7. Долгосрочные цели: что действительно можно и нельзя измерить

В задании требуется обсудить возвращение в сервис, а не доказать его увеличение любой ценой. Доступные логи позволяют **описательно** рассчитать, как частота возвращений связана с предыдущей долей дослушивания.

**ВНИМАНИЕ: исправление временных единиц после исходного run.** Тimestamps Yambda выражены в секундах, округлённых до 5-секундных значений. В исходном run условные «30 минут» и «24 часа» ошибочно считались порогами **360 секунд (6 минут)** и **17 280 секунд (4,8 часа)**. Следовательно, исторические доли 24h return **отозваны и не приводятся в этом отчёте**.

Исправленный расчёт в текущем `main`:

- сессия завершается, если до следующего прослушивания проходит **более 1800 секунд**;
- «возвращение за 24 часа» — следующий факт прослушивания через **не более 86400 секунд** после завершения сессии;
- учитываются только события, для которых существует полный 24-часовой горизонт наблюдения;
- это **ассоциация в логах**, а не причинный эффект новой политики.

Добавлен **отдельный лёгкий ручной workflow** для пересчёта этих значений на **точно той же** когорте и том же Parquet-файле (сравнение SHA-256 до анализа). Пока workflow не запущен, реальные откорректированные 24-часовые проценты **не опубликованы**.

Чтобы устанавливать эффект RL на долгосрочное удержание, нужны онлайн A/B или логирующая политика с подходящими показами/вероятностями; на пассивном датасете корреляция не равна эффекту.

## 8. Надёжность, недостающие проверки и интерпретация

- **Исходный experimental run успешно завершился**, файлы/исходники/зависимости/артефакты доступны по ссылке.
- После выполнения эксперимента обнаружен риск неупорядоченных переходов в **dense-SFT**; новая версия кода сохраняет timestamps исторических токенов и маскирует target, если предыдущий и следующий item относятся к одному bin. Для сравнения добавлен режим **`next-item-only`** (без dense-loss), с одинаковыми параметрами и данными.
- Исправлены session-time thresholds и добавлены отдельный data-only recount workflow и тесты; **пока нужен новый прогон тестов**, чтобы подтвердить эту новую ревизию.
- Сохранена обязательная прозрачность изменения протокола **после просмотра первого test**: результаты новой схемы не pre-registered до первого запуска.
- Отсутствуют надежная off-policy reward/retention-оценка, полноценный user-response simulator, полная проверка разных β и повторов по seed. Отрицательный результат не объявлен универсальным законом.

## 10. Заключение

Исследование воспроизводимо показывает, что **RL способен увеличивать прогнозируемую награду, одновременно снижая релевантность рекомендаций и усиливая повторяемость в гипотетической многошаговой генерации**. Отклонение от реальной истории накапливается, а даже независимая по пользователям reward-head не гарантирует валидности предсказания на невиденных кандидатах.

**Это честный отрицательный результат, непосредственно отвечающий критериям задания.** Полный вывод об исправленном расчёте 24h и о преимуществе/недостатке нового time-safe dense-SFT возможен только после их отдельных запусков.
